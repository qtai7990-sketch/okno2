# Единое окно — демонстрационный прототип v0.2.7

> **Статус: демонстрационный прототип.** Годится для показа банкам, обучения сотрудников на тестовых данных и согласования с ИБ банков.
> **Не годится** для реальных паспортов, боевого сервера и расчёта вознаграждения — пока не выполнены условия из раздела «До пилота» ниже.
> Что изменено по аудиту v0.1 — `docs/AUDIT_v0.1_RESPONSE.md`.

Программа стойки единого окна в аэропорту Жуковский. Три части:

| Папка | Что это | Где работает |
|---|---|---|
| `server/` | Сервер: обращения, согласия, правила маршрута, передача в банк, приём статусов от банков, отчёт смены | Российское облако (Yandex Cloud) |
| `web/` | Интерфейс стойки | Внутри приложения на планшете (и в браузере для проверки) |
| `android/` | Приложение для планшета Samsung Galaxy Tab Active5 | Планшет сотрудника стойки |
| `.github/workflows/` | Автоматическая сборка приложения и проверка сервера | GitHub |
| `tools/` | Генерация ключей, первичная настройка, имитатор банка | Компьютер администратора |
| `docs/` | Порядок развёртывания, обмен с банками, подключение сканера | — |

Персональные данные клиентов в базе хранятся только в зашифрованном виде. В QR для банка — только одноразовый код обращения.

## Шаг 1. Загрузить код на GitHub (15 минут)

1. Зарегистрируйтесь на github.com (или войдите).
2. Справа вверху «+» → **New repository**. Имя: `okno`. Выберите **Private** (закрытый). Нажмите **Create repository**.
3. На странице репозитория нажмите ссылку **uploading an existing file**.
4. Распакуйте присланный архив `okno-v0.2.7.zip` на компьютере. Перетащите в окно браузера **всё содержимое** папки `okno` (папки `server`, `web`, `android`, `tools`, `docs`, `.github` и файлы `README.md`, `.gitignore`).
   - **Важно: папка `.github` скрытая.** На Mac в Finder нажмите `Cmd + Shift + .` — она появится. На Windows включите «Показывать скрытые элементы» во вкладке «Вид».
5. Внизу нажмите **Commit changes**.

Проверка: в репозитории должна быть вкладка **Actions** с двумя сборками. Если их нет — папка `.github` не загрузилась, повторите пункт 4 только для неё.

## Шаг 2. Получить учебное приложение для планшета (10 минут, без вашего участия)

0. Один раз: Actions → «Фиксация зависимостей Android» → Run workflow → скачать `android-dependency-locks` → добавить оба файла в репозиторий (`android/app/gradle.lockfile`, `android/gradle/verification-metadata.xml`). Без них сборки планшета не запускаются.
1. Вкладка **Actions** → слева «Учебная сборка планшета (TRAINING)» → справа **Run workflow** → **Run workflow**.
2. Через 5–10 минут — зелёная галочка. Откройте запуск → внизу **Artifacts** → скачайте `OKNO-TRAINING-only-demo-apk`.
3. В архиве `OKNO-TRAINING-demo.apk` (учебная версия с демо-сканером) и `SHA256SUMS.txt` (контрольная сумма).

Рабочее приложение собирает отдельный workflow «Рабочая сборка планшета (PRODUCTION)» — только подписанное, с зашитым адресом сервера и закреплением сертификата (`docs/DEPLOY.md`, раздел 6). Без ключа подписи и настроек он не выпускает ничего.

Если сборка красная — откройте её, скопируйте текст ошибки и пришлите мне в чат.

## Шаг 3. Установить на планшет (5 минут)

1. Перешлите `OKNO-TRAINING-demo.apk` на планшет: себе в почту, мессенджер или через кабель.
2. Откройте файл на планшете. Android спросит разрешение «Установка из неизвестных источников» — разрешите для этого приложения.
3. Нажмите **Установить**. На экране появится «Единое окно».

Для рабочей эксплуатации приложение ставится через систему управления планшетами (MDM) в режиме киоска — `docs/DEPLOY.md`, раздел 5.

## Шаг 4. Сервер

Пошагово — в `docs/DEPLOY.md`. Коротко: виртуальная машина в Yandex Cloud, два адреса (для стойки и для банков), Docker, одна команда запуска, затем `bash adm.sh bootstrap-demo` на сервере выдаёт ключ планшета, ПИН старшего смены и ключи банков.

Для учебного сервера в `.env` поставьте `SIMPAD_ALLOW_DEMO_SCAN=true`. **На рабочем сервере — только `false`**: он отклоняет демо-данные и тексты согласий, не утверждённые юристом.

## Шаг 5. Первый запуск на планшете

1. Приложение просит **адрес сервера** (`https://…`) и **ключ планшета** (выдала команда `bootstrap-demo`). Ключ сохраняется в защищённом хранилище Android и больше нигде не показывается — даже интерфейсу приложения.
2. Затем — вход сотрудника: **код и ПИН** (первый — у старшего смены, выдала команда `bootstrap-demo`). Сессия закрывается через 15 минут бездействия. 5 неверных ПИН — блокировка на 15 минут.

## Что работает в v0.2

- Порядок на стойке: **согласие на обработку данных → сканирование → пакет и банк → согласия получателям → маршрут → памятка**. Без этого согласия документы не сканируются.
- Клиентский режим: на время подписи стилусом планшет показывает клиенту только текст согласия и поле подписи; очередь и чужие данные скрыты; 90 секунд без действий — блокировка; вернуть рабочий экран можно только по ПИН сотрудника.
- Согласия: неизменяемые тексты с контрольной суммой, юрлицо‑получатель и ИНН, язык объяснения, подпись **только стилусом** (палец не принимается) или фото подписанного бумажного бланка. Доказательство хранится зашифрованным. Согласие банку — конкретному банку; смена банка его отменяет.
- Правила маршрута на сервере: SIM строго после СНИЛС → Госуслуги → ЕБС → IMEI. Нотариальный перевод — по правилу банка для каждой услуги (карта, СНИЛС, ЕБС, SIM) и гражданства. **RuID ни от чего не освобождает.**
- Банковский контур: отдельный адрес с **mTLS** (сертификат банка обязателен) и списком IP; подпись запроса HMAC по методу, пути, времени, одноразовому значению и хэшу тела; ротация ключей; одноразовый QR с атомарным погашением.
- События банка: принимаются только от банка, которому передано обращение, только с его `handoff_id` и `bank_case_id`; нарушение порядка — **отказ 409** и запись в журнал отклонённых. Режим «номер дела» — статусы по официальному файлу сверки банка.
- «Со слов сотрудника банка» — отдельная запись, **не влияет** на маршрут, KPI и расчёты.
- Журнал правок, журнал действий, дубли по ключу HMAC, памятка на трёх языках, отчёт смены только по подтверждённым событиям.
- Шифрование персональных данных в базе, запрет скриншотов, только HTTPS, строгая CSP без внешних ресурсов (шрифты локальные), миграции схемы Alembic, проверка зависимостей на уязвимости в CI.

## До пилота с реальными клиентами (обязательно)

| Условие | Кто | Статус |
|---|---|---|
| Сканер Smart Engines подключён и проверен на образцах паспортов ТДЖ/УЗБ/КГЗ | Компания + Smart Engines | не начато — нужна лицензия |
| Тексты согласий утверждены юристом (152‑ФЗ) и загружены | юрист компании | не начато |
| Договор с банком + соглашение об обмене ПДн + приложение ИБ (mTLS, IP, ключи) | Компания + каждый банк | не подписано |
| Письменное правило банка по переводу для каждой услуги и гражданства | каждый банк | нет |
| Подтверждение полномочий банка на выдачу SIM (агентский договор с оператором) | каждый банк | нет |
| Договор облака в РФ, внутренние документы по 152‑ФЗ, решение по уведомлению РКН | Компания | не начато |
| Внешний тест на проникновение и проверка ИБ банка | подрядчик / банк | не начато |
| Закрепление сертификата сервера в приложении (pinning) | код готов; значения — переменные GitHub (`docs/DEPLOY.md`, разд. 6) | проверить на планшете с чужим сертификатом |
| Киоск и управляемая конфигурация через MDM, проверка выхода из приложения | Компания | не начато |
| Файлы блокировки зависимостей Android | workflow «Фиксация зависимостей Android» + проверка человеком | не сделано |
| Образ сервера из CI, подписанный, по digest из реестра | workflow готов; первый выпуск по тегу | не выпущен |
| Тариф GitHub Team, правила ветки и тегов, окружение production | Компания | не сделано |
| Бакет с версионированием, оповещения Telegram, машина учебного восстановления | Компания | не сделано |

## Чего ещё нет

- Подключение Smart Engines — после лицензии.
- Интерфейсы страховщика и бюро переводов — шаги отмечает сотрудник.
- Выдача талонов без связи: не выдаются (ложных номеров нет), сотрудник направляет в офис устно, приёмная выдаёт талон на месте.
- Печать талонов на живом принтере не проверена: код — Bluetooth Classic SPP, ESC/POS, растр `GS v 0`, проверка бумаги `DLE EOT 4`; нужна пробная печать (docs/DEPLOY.md, раздел 10).
- Голосовые фразы на таджикском, узбекском, киргизском — файлы записывает носитель языка (`web/voice/README.txt`); без них табло говорит по-русски.
- Тексты талона и памятки на таджикском, узбекском, киргизском — черновые, до запуска проверить носителем языка.
- Панель администратора — пока через `tools/` и API.
