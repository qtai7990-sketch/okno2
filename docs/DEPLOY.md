# Развёртывание сервера «Единого окна» (демонстрационный прототип v0.2.7)

Учебный сервер можно поднять сразу. Рабочий — только после условий из README, раздел «До пилота».

## 1. Что понадобится

- Учётная запись Yandex Cloud на компанию‑оператора (данные хранятся в России).
- Два адреса в домене, например `okno.simpad.ru` (стойка) и `bank-okno.simpad.ru` (только банки).
- Компьютер администратора с терминалом, `python3`, `openssl` (для сертификатов банков), `gpg` (для резервных копий).

## 2. Виртуальная машина

1. Консоль Yandex Cloud → Compute Cloud → **Создать ВМ**. Ubuntu 22.04 LTS, 2 vCPU, 4 ГБ, диск 30 ГБ SSD, статический публичный IP, доступ по SSH‑ключу.
2. Группа безопасности: входящие 22 (только с IP офиса), 80, 443. Остальное закрыто.
3. DNS: записи `A` для `okno` и `bank-okno` → IP машины.

## 3. Установка

На компьютере администратора — корневой сертификат для банков (один раз):
```bash
bash tools/bank_cert.sh ca          # создаст папку okno-pki: bank-ca.pem и bank-ca.key
scp okno-pki/bank-ca.pem ubuntu@<IP>:~/bank-ca.pem
```
`bank-ca.key` хранится офлайн (флешка в сейфе + копия). На сервер он не попадает.

На сервере:
```bash
ssh ubuntu@<IP>
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 git python3
sudo usermod -aG docker $USER && exit      # перелогиниться
ssh ubuntu@<IP>
ssh-keygen -t ed25519 -f ~/.ssh/simpad_deploy -N "" -C simpad-server
cat ~/.ssh/simpad_deploy.pub     # вставить в GitHub: репозиторий → Settings → Deploy keys → Add deploy key (без права записи)
printf 'Host github.com\n  IdentityFile ~/.ssh/simpad_deploy\n  IdentitiesOnly yes\n' >> ~/.ssh/config
git clone git@github.com:<организация>/okno.git
cd okno
mv ~/bank-ca.pem server/bank-ca.pem
```

**Учебный сервер** (образ собирается на месте):
```bash
python3 tools/genkeys.py server/.env okno.simpad.ru bank-okno.simpad.ru --training
cd server && docker compose --env-file .env -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

**Рабочий сервер** (на сервере ничего не собирается — только подписанный образ из выпуска GitHub, раздел 9):
```bash
python3 tools/genkeys.py server/.env okno.simpad.ru bank-okno.simpad.ru --production
bash tools/install_cosign.sh
echo "<токен GitHub: classic, только read:packages>" | docker login ghcr.io -u <логин GitHub> --password-stdin
export SIMPAD_GITHUB_REPO=<организация>/okno
bash tools/update.sh v0.2.7 ghcr.io/<организация>/simpad-api@sha256:<digest из выпуска>
```
При старте сервер применяет миграции схемы. Через 1–2 минуты `https://okno.simpad.ru/healthz` отвечает `{"ok": true, "db": true, ...}` (проверка включает запрос к базе).

База создаётся с нуля первой миграцией `0001`. Версия v0.1 нигде не разворачивалась, поэтому переносить старую базу не нужно; каждое следующее изменение схемы — отдельной миграцией Alembic.

**`server/.env` содержит ключ шифрования персональных данных.** Сразу скопируйте его офлайн: `scp ubuntu@<IP>:~/okno/server/.env ./env-backup` — и уберите на флешку в сейф.

### Образы и зависимости

Образы Docker закреплены по контрольной сумме (digest) прямо в `docker-compose.yml` и `Dockerfile`, зависимости Python — по хэшам (`server/requirements.lock`). CI проверяет это (`tools/ci_check_deploy.py`). Обновление образа — только осознанной правкой в репозитории через проверку (pull request).

Сеть: `private` — внутренняя (`internal: true`), в ней API и база, выхода в интернет нет; Caddy — в `edge` и `private`. Наружу открыт только Caddy (80/443). Ограничения: **API** — только для чтения, без привилегий, от непривилегированного пользователя; **база и Caddy** — без повышения привилегий (`no-new-privileges`), но с записываемыми томами данных (база, сертификаты) — это осознанное исключение. Проверки здоровья: база — `pg_isready`, API — `/healthz` с запросом к базе, Caddy — локальный API администратора. Контекст сборки образа очищен `.dockerignore` (без `.env` и ключей).

## 4. Администрирование — только на сервере

Все настройки выполняются на сервере командой `bash adm.sh` из папки `server`. Токен администратора берётся автоматически, из интернета административный вход закрыт. Список команд: `bash adm.sh help`.

```bash
cd ~/okno/server
bash adm.sh bootstrap-demo          # учебный сервер; рабочий: bootstrap-prod
```
Команда один раз выводит ключ планшета, код и ПИН старшего смены, ключи трёх банков — перенесите их в менеджер паролей.

Сотрудники и планшеты:
```bash
bash adm.sh operator-add op2 "Петров П.П." 193746
bash adm.sh operator-pin op2 507318
bash adm.sh operator-off op2
bash adm.sh device-add "Планшет стойки 2"
bash adm.sh device-off 2
```

Тексты согласий (рабочий сервер) — юрист готовит по образцу `docs/consent_texts.example.json`:
```bash
bash adm.sh text-add consent.json
bash adm.sh text-approve 1 "Иванов И.И., приказ № 12 от 05.10.2026"
```
Текст после загрузки не меняется: правка — новая версия.

## 5. Подключение банка

1. Подписаны договор, соглашение об обмене ПДн, приложение ИБ (IP банка, способ передачи ключей, срок сертификата).
2. Банк присылает запрос на сертификат (CSR). На компьютере администратора: положить его как `okno-pki/tbank.csr` → `bash tools/bank_cert.sh bank tbank`. Скрипт выпускает `tbank.crt` (отправить банку) и печатает отпечаток SHA‑256.
3. На сервере:
   ```bash
   bash adm.sh bank-set tbank legal_name="АО «ТБанк»" inn=<ИНН> cert_fingerprint=<SHA-256> mode=api sim_authority_confirmed=true 'status_map={"КОД_БАНКА":"CARD_ISSUED"}'
   bash adm.sh policy tbank card TJK no "письмо № … от …"
   nano .env      # SIMPAD_BANK_IPS=<IP банка>/32
   docker compose --env-file .env up -d
   ```
   Ночной банк (например, с 21:00 до 09:00): `bash adm.sh bank-set vtb open_from=21 open_to=9`; круглосуточно — `open_from=0 open_to=24`.
4. Ключ API и секрет подписи банку — по каналу из приложения ИБ. Ротация: `bash adm.sh bank-rotate tbank` (старые действуют 24 часа).
5. Отклонённые события: `bash adm.sh rejected`. Акт сверки банка: `bash adm.sh reconcile tbank akt.json "Акт № … от …"`.

## 6. GitHub: защита ветки, выпуск версий, рабочее приложение

**Тариф.** Для закрытого репозитория защита ветки и правила тегов доступны на тарифе **GitHub Team** (не Free). Обязательное одобрение запуска в окружении (Required reviewers) для закрытого репозитория — только на **Enterprise**; на Team вместо него работают правило тегов + список ответственных `SIMPAD_RELEASE_ACTORS`, который проверяют сами workflow.

1. Settings → Rules → Rulesets → **New branch ruleset** для `main`: изменения только через pull request, не менее 1 одобрения, обязательная проверка «Обязательная проверка (gate) / gate», запрет force push и удаления, без исключений (bypass) для кого‑либо.
2. **New tag ruleset** для `v*`: создавать, менять и удалять теги может только ответственный (bypass list — только он).
3. Settings → Environments → `production`: Deployment branches and tags → только теги `v*`. Секреты и переменные — ниже.
4. Actions → «Фиксация зависимостей Android» → Run workflow → скачать `android-dependency-locks` → добавить `android/app/gradle.lockfile` и `android/gradle/verification-metadata.xml` в репозиторий через pull request. Без них учебная и рабочая сборки планшета не запускаются.

| Тип (окружение production) | Имя | Значение |
|---|---|---|
| Secret | `SIMPAD_KEYSTORE_B64`, `SIMPAD_KEYSTORE_PASSWORD`, `SIMPAD_KEY_PASSWORD`, `SIMPAD_KEY_ALIAS` | из `tools/make_keystore.sh` |
| Variable | `SIMPAD_SIGNING_CERT_SHA256` | из `SIGNING_CERT_SHA256.txt` (`make_keystore.sh`); без неё сборка не выпускается, подпись сверяется с ней |
| Variable | `SIMPAD_SERVER_URL` | `https://okno.simpad.ru` — только `https://имя`, без порта и пути; зашивается в приложение |
| Variable | `SIMPAD_CERT_PINS` | `C5+lpZ7tcVwmwQIMcRtPbsQtWLABXhQzejna0wHFr8M=,diGVwiVYbubAI3RW4hB9xU8e/CH2GnkuvVFZE8zmgzI=` — корни Let's Encrypt ISRG Root X1 и X2 |
| Variable | `SIMPAD_RELEASE_ACTORS` | логин(ы) GitHub ответственного через запятую |

**Выпуск версии:** ответственный создаёт тег `v0.2.7` (Releases → Draft a new release). Автоматически запускаются:
- «Выпуск образа сервера (PRODUCTION)» — образ в реестре GitHub по digest, SBOM, подпись sigstore; digest — в итогах запуска и в `release-digest.txt`;
- «Рабочая сборка планшета (PRODUCTION)» — подписанный APK, сверка сертификата подписи, `SHA256SUMS.txt`, `VERSION.txt` (versionCode).

Закрепление сертификата действует до 01.06.2035 (срок корня ISRG Root X1). Устаревшие приложения отсекает сервер: `SIMPAD_MIN_APP_VERSION` в `server/.env` — минимальный versionCode; более старые версии получают отказ и должны быть обновлены через MDM.

Почему закреплены корни, а не сертификат сервера: Caddy обновляет сертификат каждые ~60 дней с новым ключом. Корни ISRG стабильны; Caddy выпускает сертификаты только у Let's Encrypt (`cert_issuer acme`).

## 7. Планшеты в режиме киоска

Samsung Knox Suite или российский MDM — обязательно. **Рабочая сборка без киоска не работает**: пока MDM не разрешил приложению режим киоска, запросы к серверу не отправляются, на экране — предупреждение.
- установить APK из артефакта `OKNO-PRODUCTION-signed-apk`, сверив SHA‑256 из `SHA256SUMS.txt`;
- разрешить приложению режим киоска (lock task allowlist) — приложение входит в него само; в allowlist добавить и системную камеру (фото бумажного бланка);
- разрешение «Камера» выдать политикой MDM заранее (системный запрос разрешения в киоске может быть недоступен);
- управляемая конфигурация приложения: `device_key` — ключ планшета из `bash adm.sh device-add`; при заданном `device_key` сменить адрес сервера в приложении нельзя;
- запрет установки других приложений, отладки по USB, разблокировки загрузчика, снимков и трансляции экрана; шифрование; удалённая блокировка и стирание; печать — только на принтер стойки;
- проверка на планшете: «Домой», «Недавние», шторка не выводят из приложения; при уходе приложения с экрана оно блокируется и требует ПИН.

Учебная сборка (`OKNO-TRAINING-only-demo-apk`) — только для учебного сервера: адрес вводится вручную, закрепления и требования киоска нет. При смене адреса обязательно вводится новый ключ планшета.

## 8. Резервные копии — зашифрованные, вне сервера, с проверкой и оповещениями

Подготовка (один раз):
1. На компьютере администратора: пара ключей gpg для копий. На сервер — **только открытый** ключ; сверить отпечаток по независимому каналу.
2. Yandex Object Storage: бакет с **версионированием**; сервисный аккаунт с правом только на запись и чтение метаданных (без удаления) — для рабочего сервера; отдельный аккаунт только на чтение — для машины восстановления.
3. Бот Telegram для оповещений (через @BotFather), id чата ответственного.

На сервере:
```bash
sudo apt-get install -y awscli
mkdir -p ~/.aws && chmod 700 ~/.aws && nano ~/.aws/credentials && chmod 600 ~/.aws/credentials   # ключи сервисного аккаунта
gpg --import simpad-backup.pub.asc
sudo mkdir -p /etc/simpad && sudo install -m 600 tools/systemd/ops.env.example /etc/simpad/ops.env && sudo nano /etc/simpad/ops.env
sudo cp tools/systemd/simpad-*.service tools/systemd/simpad-*.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now simpad-backup.timer simpad-backup-check.timer
sudo systemctl start simpad-backup.service simpad-backup-check.service
bash tools/alert.sh "проверка оповещений"           # сообщение должно прийти в Telegram
```
- `tools/backup.sh` — дамп PostgreSQL, проверка оглавления, шифрование, контрольная сумма, выгрузка в бакет со сверкой размера; **без бакета завершается ошибкой** (учебный сервер: `SIMPAD_BACKUP_LOCAL_ONLY=1`); одновременный запуск исключён блокировкой; имена уникальны.
- `tools/backup_check.sh` (ежедневно 09:10) — свежесть не более 26 ч, файл на месте, контрольная сумма совпадает, объект есть в бакете.
- Любой сбой службы — сообщение в Telegram (`simpad-alert@`).

**Учебное восстановление — ежемесячно, автоматически, НЕ на рабочем сервере**: отдельная машина (компьютер администратора или изолированная ВМ) с закрытым ключом gpg и доступом к бакету только на чтение:
```bash
sudo install -m 600 /dev/null /etc/simpad/drill.env   # SIMPAD_BACKUP_BUCKET, AWS_SHARED_CREDENTIALS_FILE, SIMPAD_ALERT_TG_*
sudo cp tools/systemd/simpad-restore-drill.* tools/systemd/simpad-alert@.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now simpad-restore-drill.timer
```
1‑го числа каждого месяца: скачивается последняя копия, проверяется контрольная сумма (обязательна), расшифровывается, восстанавливается во временную PostgreSQL, считаются строки; результат — в `~/simpad-drill/drill.log` (права 600) и в Telegram. Сбой — оповещение.

Удаление закрытых обращений старше 30 дней (срок — по политике ПДн): `bash adm.sh purge 30`. Удаляются персональные данные, согласия с доказательствами, шаги, правки. Остаются журнал действий и события банков (без персональных данных) — для сверки.

## 10. Электронная очередь: талоны, поясной принтер, табло (v0.2.6–v0.2.7)

Схема: планшет зала выдаёт талон (язык клиента + номер, персональных данных нет) → поясной принтер печатает талон с QR →
на входе в офис талон сканируют (очередь — по времени прихода) → табло вызывает «А317 → Стойка 7» голосом →
на стойке «Клиент подошёл» открывает обращение, привязанное к талону → после передачи в банк «Вызвать к окну банка».

**Роли устройств** (ключ устройства определяет, что ему доступно):

| Роль | Что делает | Как создать |
|---|---|---|
| `hall` | только выдача талонов своей серии | `bash adm.sh device-add "Зал 2" hall В` |
| `reception` | приём талонов, талон без зала, обзор очереди | `bash adm.sh device-add "Приёмная" reception Р` |
| `desk` | вызов, оформление, всё остальное | `bash adm.sh device-add "Стойка 2" desk 2` |
| `board` | только табло (номера и стойки), вход сотрудника запрещён | `bash adm.sh device-add "Табло" board` |

Серия — одна буква из `ABEKMHPCTX` (одинаково выглядят в латинице и кириллице; кириллицу при вводе система понимает).
Две активные серии на одной стойке совпадать не могут. `bash adm.sh devices` — список, `device-set <id> station=3` — правка.

**Окно банка на табло:** `bash adm.sh bank-set <банк> window=12`.
**Текст «как пройти» на талоне:** `bash adm.sh ticket-text ru "…"` (также `tj`, `uz`, `ky`; переводы — после проверки носителем языка).
**Отчёт:** `bash adm.sh queue-report [ГГГГ-ММ-ДД]` — выдано, пришли, обслужены, ожидание, по сотрудникам зала.

**Принтер** — Bluetooth Classic (SPP), ESC/POS, бумага 58 или 80 мм (например, MERTECH MPRINT E300 Bluetooth).
Сопряжение — в настройках Android до включения киоска (делает администратор).
**Рабочая сборка печатает только на принтер из MDM:** управляемая конфигурация приложения `printer_mac` (адрес Bluetooth,
например `00:11:22:33:44:55`), `printer_dots` (576 — бумага 80 мм, 384 — 58 мм), `printer_name` (подпись на экране).
Сотрудник смены принтер не выбирает. **Учебная сборка** позволяет выбрать принтер в приложении: «Настройка планшета» →
«Выбрать принтер» → «Пробная печать». Талон печатается картинкой, поэтому таджикские и киргизские буквы не зависят от
кодовых страниц принтера. Перед печатью запрашивается датчик бумаги (`DLE EOT 4`): нет бумаги — печать не начинается;
принтер, который на запрос не отвечает, печатает как обычно. В MDM: разрешить Bluetooth и выдать приложению разрешение
«Устройства поблизости» (BLUETOOTH_CONNECT).

**Повторная выдача:** планшет отправляет заголовок `Idempotency-Key`; повтор запроса (потеря ответа, повторное касание
того же языка в течение 2 минут) возвращает тот же талон с тем же QR. QR выводится из id талона секретом сервера, в базе —
только хэш. Отметка «напечатан» попадает в отчёт очереди (`printed_hall`).

**Натурная проверка одного комплекта до покупки остальных:** сопряжение после перезагрузки обоих устройств; 100 талонов
подряд без пропусков и зависаний; 95 % талонов — не дольше 3 секунд при установленном соединении; 20 талонов читаются
офисным 2D‑сканером с первой–второй попытки; видны буквы Ҷ Ӯ Қ Ғ Ҳ Ң Ө Ү; нет бумаги / выключен / вне зоны / разряжен —
понятная ошибка и допечатка того же талона; в рабочей сборке нельзя выбрать другой Bluetooth‑принтер.

**Табло** — любой экран с Chrome: `https://<домен стойки>/ui/board.html`, ключ устройства роли `board`, в начале смены
один раз «Включить табло со звуком» (браузер не даёт странице говорить без нажатия). Голос — русский голос системы;
если его нет, табло показывает предупреждение и подаёт только звуковой сигнал. После русской фразы звучит записанная фраза
на языке клиента (`web/voice/<tj|uz|ky>-desk.mp3` и `-bank.mp3`, см. `web/voice/README.txt`). Вызов к стойке, на который
не подошли, повторяется через 40 секунд, не больше двух раз.

**Приёмная** — ручной 2D‑сканер в режиме клавиатуры (USB или Bluetooth HID) с окончанием Enter. QR талона — только цифры,
поэтому раскладка клавиатуры не влияет.
